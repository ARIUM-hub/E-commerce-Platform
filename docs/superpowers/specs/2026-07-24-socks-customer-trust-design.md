# 袜子商城客服与信任体系设计文档

- 日期：2026-07-24
- 主题：为 `socks-product-list.html` 增加客服与信任体系
- 推荐方案：单页商城内置 Trust Center，并接入演示级真实后端接口

## 1. 目标

把当前袜子商城从“能浏览、加购、结算、下单”的交易演示，继续升级为更像真实商城的完整购物体验。用户应该能在站内清楚找到退换政策、配送说明、隐私政策、服务条款、FAQ 和联系入口，并且这些入口要延续现有商城头部、页脚、路由、多语言和后端数据流。

本阶段重点不是接入真实客服系统，而是建立可信的商城支持层：政策内容结构化展示，常见问题可展开，联系表单可校验并生成演示工单记录。

## 2. 当前上下文

现有项目已经具备：

- 单页多视图商城入口：`socks-product-list.html`
- 现有视图：列表、详情、结算、订单、订单历史、登录注册、地址管理
- 全站头部与页脚壳层
- SQLite-backed 商品、SKU、购物车、用户、地址、订单和营销数据
- 多语言文案体系
- 顶部帮助现有入口：`data-site-help-link`
- 顶部退换现有入口：`data-site-returns-link`
- 页脚购买帮助、配送说明、支持与政策现有栏目

本功能应复用这些入口和壳层，不新建割裂的静态 HTML 页面。

## 3. 范围

### 3.1 包含

- 新增 `support` 视图：`/socks-product-list.html?view=support`
- 支持锚点式分区跳转：`section=returns`、`section=delivery`、`section=privacy`、`section=terms`、`section=faq`、`section=contact`
- 退换政策展示
- 配送说明展示
- 隐私政策展示
- 服务条款展示
- FAQ 折叠面板
- 联系入口表单
- 后端返回信任中心内容：`GET /api/trust-center`
- 后端接收联系请求：`POST /api/support/contact`
- SQLite 存储联系工单
- 顶部导航与页脚链接接入新视图
- 中文与英文文案支持
- 基础可访问性和 UI 测试覆盖

### 3.2 不包含

- 真实邮件发送
- 在线客服聊天
- 人工客服后台
- 管理端政策编辑器
- 富文本 CMS
- 文件上传
- 真实物流轨迹查询
- 法律级合规审计

## 4. 设计方案

采用“单页商城内置 Trust Center”：

- 主入口仍是 `socks-product-list.html`
- 新增视图 key：`support`
- 顶部、页脚、详情页、结算页、订单页都链接到同一个支持中心
- 政策内容通过后端接口返回，前端按 section 渲染和定位
- 联系表单提交到后端，后端写入 SQLite 并返回工单号

这种方式比纯静态政策页更真实，也比拆分多个 HTML 页面更容易维护现有头部、页脚、多语言和路由状态。

## 5. 信息架构

### 5.1 Trust Center 页面结构

页面包含四层：

- 顶部面包屑：`首页 / 帮助中心`
- 页面标题区：说明这是袜子商城的帮助与政策中心
- 左侧或顶部 section 导航：退换、配送、隐私、条款、FAQ、联系我们
- 主内容区：展示当前 section，并保留其他 section 的快速入口

移动端使用横向可滚动 section 标签或紧凑卡片导航，避免固定宽度造成横向溢出。

### 5.2 政策分区

退换政策：

- 说明可退换条件
- 说明袜子类商品的卫生与未穿着要求
- 说明退款处理周期
- 提供“联系支持”入口

配送说明：

- 说明标准配送、加急配送、免邮条件
- 说明订单预计送达来自当前结算逻辑
- 提供配送异常处理说明

隐私政策：

- 说明演示站点会使用会话 ID、购物车、地址和订单信息
- 说明数据仅用于当前演示商城流程
- 说明不会接入真实第三方广告或追踪

服务条款：

- 说明当前项目是演示商城
- 说明价格、库存、优惠、订单状态均为演示数据
- 说明用户提交信息仅用于演示流程

FAQ：

- 使用可展开折叠面板
- 覆盖尺码、库存、优惠券、订单、退换、账户等问题
- 支持键盘操作和 `aria-expanded`

联系入口：

- 表单字段：姓名、联系方式、问题类型、订单号、消息内容
- 问题类型：订单问题、退换问题、配送问题、账户问题、商品咨询、其他
- 未登录用户也可以提交
- 已登录用户提交时，后端可关联当前 `user_id`
- 成功后展示工单号和预计响应时间

## 6. 后端接口设计

### 6.1 `GET /api/trust-center`

返回当前 locale 下的政策与 FAQ 内容。

查询参数：

- `locale`

响应字段：

- `sections`
- `faqs`
- `contactTopics`
- `updatedAt`

内容可先使用服务端 seed 常量初始化，后续如果需要管理端再迁移到完整 CMS。

### 6.2 `POST /api/support/contact`

接收联系请求并写入 SQLite。

请求字段：

- `name`
- `contact`
- `topic`
- `orderId`
- `message`
- `locale`

后端行为：

- 校验必填字段
- 校验联系方式长度与消息长度
- 如果当前会话已登录，关联 `user_id`
- 生成工单号，例如 `SUP-20260724-0001`
- 写入 `support_tickets`
- 返回工单摘要

### 6.3 错误码

沿用标准 API 错误信封，新增错误码：

- `SUPPORT_NAME_REQUIRED`
- `SUPPORT_CONTACT_REQUIRED`
- `SUPPORT_TOPIC_REQUIRED`
- `SUPPORT_MESSAGE_REQUIRED`
- `SUPPORT_MESSAGE_TOO_LONG`
- `SUPPORT_TOPIC_INVALID`

前端将错误展示在对应字段附近，并保留顶部 toast 作为轻量反馈。

## 7. 数据模型

新增 SQLite 表：`support_tickets`

建议字段：

- `id`
- `ticket_number`
- `session_id`
- `user_id`
- `name`
- `contact`
- `topic`
- `order_id`
- `message`
- `locale`
- `status`
- `created_at`
- `updated_at`

初始状态：

- `open`

本阶段不做客服处理后台，因此状态只作为未来订单生命周期或客服后台的扩展点。

## 8. 前端交互

### 8.1 路由

新增视图判断：

- `view=support` 渲染 Trust Center
- `section` 控制默认定位和高亮
- 无效 section 默认落到 `faq`

从其他页面进入支持中心时，应保留商城壳层，并提供返回商城入口。

### 8.2 顶部与页脚链接

顶部：

- “帮助中心”跳转 `?view=support&section=faq`
- “退换说明”跳转 `?view=support&section=returns`

页脚：

- 购买帮助链接到 FAQ 或联系入口
- 配送说明链接到配送 section
- 退换说明链接到退换 section
- 隐私政策链接到隐私 section
- 服务条款链接到条款 section
- 联系我们链接到联系 section

### 8.3 FAQ

- 默认展开第一个高频问题
- 点击问题切换展开状态
- 支持键盘回车和空格
- 只通过高度、透明度和图标方向变化表达展开，不造成布局跳动

### 8.4 联系表单

- 提交时按钮进入 loading 状态
- 校验失败显示字段级错误
- 成功后展示工单成功卡片
- 成功卡片包含工单号、问题类型和预计响应时间
- 用户可继续返回商城或再提交一个问题

## 9. 视觉与体验

整体延续当前黑、白、灰的高信息密度商城风格，避免突然变成营销落地页。

设计重点：

- 政策内容要像真实商城帮助中心，信息清晰、可扫描
- FAQ 卡片要有明确交互状态
- 联系入口要看起来可信，但不暗示真实客服已经接通
- 移动端优先保证 section 导航、表单和 FAQ 的触控尺寸
- 所有按钮、链接、折叠项保留清晰 focus 状态

## 10. 多语言

新增文案进入现有 i18n 字典：

- 页面标题
- section 名称
- 政策正文
- FAQ 问答
- 表单标签
- 表单错误
- 成功反馈
- 顶部与页脚链接文案

中文和英文使用同一结构，避免两种语言出现不同模块。

## 11. 测试策略

### 11.1 API 测试

- `GET /api/trust-center` 返回政策分区、FAQ 和联系主题
- `GET /api/trust-center?locale=en-US` 返回英文内容
- `POST /api/support/contact` 成功创建工单
- 缺少姓名、联系方式、主题或消息时返回标准错误
- 非法主题返回 `SUPPORT_TOPIC_INVALID`
- 已登录用户提交时关联用户

### 11.2 UI 测试

- 顶部帮助中心入口打开 support 视图
- 顶部退换说明入口定位到退换 section
- 页脚隐私政策、服务条款、配送说明、联系我们入口可跳转
- FAQ 可展开和收起
- 联系表单校验错误展示在字段附近
- 联系表单成功后展示工单号
- support 视图在移动宽度无横向溢出

## 12. 验收标准

- 用户可以从顶部和页脚进入客服与政策中心
- 六个核心模块都可访问：退换、配送、隐私、条款、FAQ、联系
- 联系请求不只是前端假状态，而是写入 SQLite 并返回工单号
- 中文和英文都能显示完整支持内容
- 不影响现有商品列表、详情、购物车、结算、订单和营销流程
- 聚焦 API 与 UI 测试通过
