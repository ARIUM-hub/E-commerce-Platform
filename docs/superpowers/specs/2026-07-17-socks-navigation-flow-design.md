# 袜子商城页面跳转流增强设计文档

- 日期：2026-07-17
- 主题：完善 `socks-product-list.html` 内的推荐卡、购物车抽屉与订单页返回链路
- 方向：让商品浏览、加购、结算、回店继续逛这条路径更顺手，更接近真实商城体验

## 1. 目标

在已经完成的列表页、详情页、购物车抽屉、订单页基础上，继续补强“页面跳转”这一层体验，让用户从任意入口进入商品详情、购物车、订单页后，都能更顺畅地继续浏览。

本次主要解决 3 个问题：

- 详情页推荐卡虽然可见，但需要保证点击后延续当前浏览上下文
- 购物车抽屉缺少“查看商品”入口，用户很难从购物车回到对应单品详情
- 订单页缺少清晰的“继续购物”返回入口，浏览链路在下单确认后会断开

## 2. 范围

本次设计包含：

- 详情页推荐卡跳转增强
- 购物车抽屉商品详情跳转入口
- 订单页 `Continue shopping` 返回入口
- 轻量来源上下文状态，用于保留筛选与排序来源

本次设计不包含：

- 新的独立 HTML 页面
- 新的后端接口
- 订单历史页
- 面包屑体系
- 多级来源回退栈

## 3. 设计方向

继续沿用“单一入口多视图”方案：

- 商城主入口仍然是 `socks-product-list.html`
- 商品详情页仍然是 `?view=detail&id=<productId>`
- 订单页仍然是 `?view=order`

所有增强都优先复用现有 query 参数与前端状态，不新增额外页面文件和服务端路由。

核心原则：

- 尽量保留用户当前的 `filter` / `sort`
- 能从哪里进入，就尽量能顺着原路径继续浏览
- 跳转规则清晰、可预测，不做“智能但不可控”的隐式回跳

## 4. 用户路径

### 4.1 推荐卡路径

用户在详情页看到 `You may also like` 后，点击任意推荐商品卡：

- 进入对应商品详情页
- URL 保留当前 `filter` 与 `sort`
- 用户可继续使用 `Previous` / `Next` 在同一浏览上下文中切换

示例：

```text
/socks-product-list.html?view=detail&id=sock-02&filter=sport&sort=price-desc
  -> 点击推荐卡 sock-04
/socks-product-list.html?view=detail&id=sock-04&filter=sport&sort=price-desc
```

### 4.2 购物车抽屉路径

用户在列表页或详情页打开购物车抽屉后，可在每个购物车商品条目中看到 `查看商品`：

- 点击后进入对应商品详情页
- 如果当前页面已有明确的 `filter` / `sort` 上下文，则复用该上下文
- 如果当前没有明确来源，则退回默认详情地址

### 4.3 订单页路径

用户完成结算进入订单页后，页面提供 `Continue shopping`：

- 如果结算前记录过来源列表地址，则回到该地址
- 如果没有可用来源，则回到默认商城列表页 `/socks-product-list.html`

这样用户在订单确认后仍可以自然回到商城继续浏览。

## 5. 状态设计

本次只新增轻量前端导航状态，不改购物车或商品数据结构。

建议增加一份前端来源上下文对象，内容包括：

- 当前激活的 `filter`
- 当前激活的 `sort`
- 最近一次可返回的商城列表地址

该状态用途：

- 为详情页推荐卡生成上下文一致的详情链接
- 为购物车抽屉中的 `查看商品` 生成详情链接
- 为订单页的 `Continue shopping` 生成返回列表地址

来源列表地址的生成规则：

- 在商城列表页渲染时，根据当前 `filter` / `sort` 计算标准列表地址
- 在用户进入详情页、打开购物车、进入订单页前，都优先保留最近一次有效列表地址

## 6. 跳转规则

### 6.1 详情页推荐卡

- 推荐卡链接继续使用详情页主入口
- 链接格式为：

```text
/socks-product-list.html?view=detail&id=<productId>&filter=<activeFilter>&sort=<activeSort>
```

- 当 `filter=all` 或 `sort=recommended` 时，可继续沿用当前项目已有的省略规则

### 6.2 购物车抽屉查看商品

每个购物车条目增加一个轻量链接：

- 文案：`查看商品`
- 目标：对应商品详情页
- 上下文优先级：
  - 当前页面的 `filter` / `sort`
  - 最近一次记录的列表来源
  - 默认详情地址

### 6.3 订单页 Continue shopping

订单页增加一个明确返回入口：

- 文案：`Continue shopping`
- 链接目标优先使用最近一次记录的商城列表地址
- 若状态缺失，则回到：

```text
/socks-product-list.html
```

## 7. 视觉与交互

- 推荐卡保持当前黑白灰视觉语言，不新增复杂样式层级
- 购物车抽屉里的 `查看商品` 使用低干扰文本链接或次级按钮样式
- `Continue shopping` 在订单页中作为清晰可见但低于主确认信息的辅助 CTA
- 所有新增跳转入口都应具备明确 hover/focus 状态，保持与当前页面运动语言一致

## 8. 异常与回退

- 如果购物车中的商品在商品数据中找不到，`查看商品` 不显示
- 如果来源上下文缺失，则使用默认详情或默认列表地址，不阻塞页面渲染
- 如果订单页没有来源记录，`Continue shopping` 仍然可用，只是回到默认商城首页

## 9. 测试设计

需要新增或补充以下验证：

- 详情页推荐卡点击后进入新详情页，并保留原有 `filter` / `sort`
- 购物车抽屉中的 `查看商品` 能跳到对应详情页
- 订单页中的 `Continue shopping` 能回到正确商城列表地址

同时保持以下已有能力不回退：

- 列表页到详情页跳转
- 详情页返回列表页
- 详情页 `Previous` / `Next` 连续浏览
- 购物车抽屉正常开合与结算

## 10. 验收标准

- 推荐卡点击后可进入对应详情页
- 推荐卡跳转后继续保留当前浏览上下文
- 购物车抽屉中每个有效商品都可跳转到详情页
- 订单页存在明确的 `Continue shopping` 返回入口
- 返回商城时尽量保留用户原来的筛选和排序状态
- 不新增后端接口
- 不新增新的独立页面文件
