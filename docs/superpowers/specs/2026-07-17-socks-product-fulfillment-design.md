# 袜子商品卡配送与库存信号设计文档

- 日期：2026-07-17
- 主题：为 `socks-product-list.html` 的商品卡增加配送承诺与库存信号
- 方向：在现有评分增强基础上，继续补足真实商城购买决策信息

## 1. 目标

在保持当前黑、白、灰简约电商风格的前提下，为袜子商品卡增加两类更接近真实商城的信号：

- 配送承诺
- 库存状态

用户在浏览商品卡时，除了价格、评分、评论数之外，还可以更快判断：

- 是否有免邮或配送利益点
- 预计何时送达
- 当前库存是否紧张

## 2. 范围

本次设计包含：

- 商品数据字段扩展
- 商品卡配送信息区设计
- 商品卡库存提示设计
- 接口返回字段扩展
- 页面渲染与测试补充

本次设计不包含：

- 实时库存扣减
- 配送地址输入
- Prime 会员体系
- 运费计算器
- 订单和结算流程

## 3. 设计方向

本轮采用“轻真实商城信号”方案：

- 保持当前卡片克制感
- 引入真实电商常见的配送与库存信息
- 不使用强烈平台色彩或高密度促销样式

结果应体现为：

- 商品卡更像真实可购买页面
- 决策信息更完整
- 版面仍然简洁，不显吵闹

## 4. 信息层级

商品卡信息层级调整为：

1. 系列名、商品标题、品类
2. 价格、原价、折扣
3. 评分区
4. 描述文案
5. 配送与库存信号
6. 尺码选择与加入购物车

这样安排的原因：

- 标题和价格仍然是第一层
- 评分负责口碑判断
- 配送与库存作为临近购买动作前的补充信号

## 5. 配送区设计

### 5.1 组成内容

配送区包含两段信息：

- `shippingLabel`
  示例：`FREE delivery`
- `deliveryEstimate`
  示例：`Get it by Sunday, July 19`

推荐表现为上下两行，保持节奏清楚：

```text
FREE delivery
Get it by Sunday, July 19
```

### 5.2 视觉规则

- `shippingLabel` 使用更深一层字重，作为轻利益点
- `deliveryEstimate` 使用中灰色，避免抢价格信息
- 不使用蓝色链接感
- 不使用品牌会员标识

## 6. 库存信号设计

### 6.1 数据状态

库存区通过两个字段驱动：

- `stockLabel`
- `isLowStock`

示例：

- `In stock`
- `Only 6 left in stock`

### 6.2 展现规则

- `isLowStock: false` 时，显示普通库存文案
- `isLowStock: true` 时，显示更强调的紧张库存文案
- 低库存仅在部分商品展示，不能全量出现

### 6.3 风格边界

- 仍保持灰阶体系
- 不用高饱和红色
- 不叠加感叹号或夸张促销文案

## 7. 数据设计

每个商品新增以下字段：

- `shippingLabel`
- `deliveryEstimate`
- `stockLabel`
- `isLowStock`

示例结构：

```json
{
  "id": "sock-01",
  "title": "极简中筒袜",
  "shippingLabel": "FREE delivery",
  "deliveryEstimate": "Get it by Sunday, July 19",
  "stockLabel": "In stock",
  "isLowStock": false
}
```

字段规则：

- `shippingLabel` 使用字符串
- `deliveryEstimate` 使用字符串
- `stockLabel` 使用字符串
- `isLowStock` 使用布尔值
- `isLowStock` 与 `isRecommended`、`isTopRated` 保持独立，不能互相推导

## 8. 前端渲染设计

前端商品卡新增一个 `product-card__commerce` 区块，放在描述下方、尺码区上方，负责：

- 渲染配送文案
- 渲染送达时间
- 渲染库存文案
- 根据 `isLowStock` 切换库存样式

## 9. 响应式要求

- 移动端下配送与库存区可换成纵向堆叠
- 不允许出现文案重叠或裁切
- 库存提示在窄屏下仍需完整可读

## 10. 测试设计

需要补充：

- API 字段契约测试
- 指定商品的配送与库存字段回归测试
- 商品卡渲染测试
- 低库存样式条件测试
- 移动端可读性测试

## 11. 验收标准

- `GET /api/products` 返回配送与库存字段
- 商品卡可见配送与库存信息
- 指定商品显示低库存文案
- 页面在移动端无明显破版
- 不影响现有筛选、排序、购物车与评分功能

## 12. 实现备注

- 这是商品卡真实感增强的下一步，不是整页改版
- 本轮仍保持“静态数据驱动 + 真实接口返回”的实现方式
- 若后续继续增强，可再补近期购买人数或更细的配送利益点
