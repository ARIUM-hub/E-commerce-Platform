# 袜子商城整站壳层设计文档

- 日期：2026-07-20
- 主题：为 `socks-product-list.html` 增加更像真实商城的整站首页壳层
- 方向：在保留现有列表页、详情页、购物车抽屉、订单页和多语言能力的基础上，补齐全站级头部、搜索、频道入口和页脚

## 1. 目标

把当前更偏“商品频道页”的袜子商城，升级成更像真实电商站内页面的统一商城壳层：

- 在列表页、详情页、订单页共享同一套站点头部和页脚
- 让页面视觉层级更接近高信息密度商城首页
- 让搜索和顶部导航接入现有真实商品数据流
- 不打断已经完成的详情、购物车、订单和多语言链路

## 2. 范围

本次设计包含：

- 全站三层头部
- 全站统一页脚
- storefront 专属的品类入口区和频道导流区
- 基于真实商品数据的搜索功能
- 顶部导航与现有分类筛选的联动
- 搜索词在 URL、详情页、订单页中的上下文保留

本次设计不包含：

- 新的独立 HTML 页面
- 新的多部门商品体系
- 用户登录系统
- 支付、地址、结算表单重构
- 推荐算法或个性化推荐
- 履约日期真实性修正

## 3. 设计方向

继续采用“单一入口多视图”方案：

- 主页面仍然是 `socks-product-list.html`
- 商品详情页继续使用 `?view=detail&id=<productId>`
- 订单页继续使用 `?view=order`

新增的整站壳层不拆成独立页面，而是包裹当前的三种主视图：

- `storefront`
- `detail`
- `order`

这样可以最大化复用现有：

- 商品接口
- 购物车状态
- 多语言切换
- 详情返回逻辑
- 订单页来源上下文

## 4. 页面结构

### 4.1 全站头部

头部采用三层结构，并在三个视图中统一显示。

#### 第一层：促销与服务提示条

用途：

- 提供包邮、履约、活动等轻量信息
- 放置帮助和语言类辅助入口

建议内容：

- 左侧：包邮提醒、活动利益点、配送说明
- 右侧：语言切换、帮助中心、退换说明

#### 第二层：主商城头部

用途：

- 建立“像真实商城站点”的第一视觉印象
- 提供主搜索入口
- 承载账户、订单、购物车等高频功能入口

结构建议：

- 左侧：品牌标识、部门提示
- 中间：搜索框与搜索按钮
- 右侧：账户入口、订单入口、购物车入口

风格原则：

- 信息密度高于当前版本
- 搜索框成为视觉中心
- 不直接复刻亚马逊蓝橙配色，仍保持黑白灰

#### 第三层：站内频道导航条

用途：

- 建立袜子频道的商城层级感
- 提供可点击的真实筛选入口

建议入口：

- All Socks
- Sport
- Daily
- Crew
- No-Show
- Multipack
- Best Sellers
- Deals

约束：

- 视觉上像多层商城导航
- 实际主营类目仍然只有袜子
- 与现有 `filter` 状态共享同一套筛选逻辑

### 4.2 storefront 内容区

storefront 在保留现有列表、筛选栏、排序栏和商品卡的基础上，新增一层更像商城频道首页的入口区。

新增模块：

- 品类快捷入口卡
- 场景化入口
- 活动入口
- 热门搜索词或搜索引导

现有 hero 调整为“袜子频道说明区”，不再作为单纯的 landing hero。

### 4.3 detail 内容区

detail 继续复用现有单品详情布局，但上方由统一商城头部接管，不单独使用“页面像独立落地页”的视觉逻辑。

detail 仍保留：

- 返回入口
- 来源提示
- breadcrumb
- previous / next 浏览
- 推荐商品
- 购物车入口

### 4.4 order 内容区

order 继续复用现有订单确认逻辑，但挂在完整商城壳层之下，保持用户仍处于同一商城站内的感受。

order 仍保留：

- 订单摘要
- Continue shopping
- 来源说明
- 空状态兜底

### 4.5 全站页脚

页脚采用两层结构，并在三个视图中统一显示。

第一层：

- 购买帮助
- 配送说明
- 退换说明
- 客服支持

第二层：

- 语言 / 地区提示
- 次级帮助链接
- 版权信息

## 5. 数据与状态设计

### 5.1 搜索状态

新增前端状态：

- `activeQuery`

用途：

- 表示当前 storefront 商品搜索词
- 允许与 `filter` 和 `sort` 叠加

搜索范围限定为当前袜子商品的：

- `title`
- `description`
- `categoryLabel`

### 5.2 URL 状态

为保证刷新、回退和跨视图跳转时上下文不丢失，搜索词进入 URL：

```text
/socks-product-list.html?filter=sport&sort=price-desc&q=train
```

规则：

- `q` 可为空
- `q` 与 `filter`、`sort` 并存
- detail / order / cart drawer 返回 storefront 时尽量保留 `q`

### 5.3 顶部导航与列表筛选状态统一

顶部频道导航不单独发明新状态，而是复用现有：

- `filter`
- `sort`

这样可以保证：

- 顶部导航点击后能真实影响商品列表
- 工具栏筛选与顶部频道导航结果一致
- 测试覆盖更集中

### 5.4 搜索与筛选执行顺序

商品结果处理顺序统一为：

1. 先按 `filter` 过滤
2. 再按 `q` 做搜索匹配
3. 最后按 `sort` 排序

这样用户行为更可预测。

## 6. 接口设计

继续复用现有 `GET /api/products`，新增可选查询参数：

- `q`
- `locale`
- `filter`
- `sort`

后端职责：

- 先按 locale 产出本地化商品内容
- 再按本地化后的 `title / description / categoryLabel` 做搜索匹配
- 最后返回排序后的结果集

这样可以保证：

- 中文界面下可以搜中文
- 英文界面下可以搜英文
- storefront、detail、order 触发搜索时都走同一套真实结果源

## 7. 交互设计

### 7.1 搜索

storefront：

- 用户输入搜索词后提交
- 页面刷新当前商品列表
- 结果数同步变化
- URL 同步写入 `q`

detail / order：

- 顶部搜索框仍然可用
- 提交后统一跳转回 storefront
- 保留搜索词，并尽量带上当前有效 `filter` / `sort`

### 7.2 顶部频道导航

点击任意频道入口时：

- 若当前不在 storefront，则跳回 storefront
- 同步写入对应 `filter`
- 保留当前有效 `q` 与 `sort`

### 7.3 品类入口区

仅 storefront 显示。

入口分为两类：

- 真实筛选入口
- 真实搜索引导入口

要求：

- 点击后必须真实影响商品结果
- 不做纯装饰性假按钮

### 7.4 多语言

新增头部、页脚、品类入口区文案必须进入现有 i18n 体系。

要求：

- 中文和英文头部结构一致
- 搜索占位文案、导航文案、页脚文案都可切换
- 搜索逻辑跟随当前 locale 数据工作

## 8. 技术实现边界

本次建议继续以 [socks-product-list.html](/D:/Poject/ai/socks-product-list.html) 为核心承载文件，不拆新页面。

但为了避免文件继续失控，建议在同文件内做结构化拆分：

- 头部相关渲染函数
- 页脚相关渲染函数
- 搜索参数辅助函数
- storefront 频道入口渲染函数
- 顶部导航状态同步函数

这样即使仍是单文件，也能保持后续演进可控。

## 9. 测试设计

需要补充以下回归与新增测试：

- 列表页、详情页、订单页都可见统一头部
- 列表页、详情页、订单页都可见统一页脚
- storefront 搜索会真实请求带 `q` 的 `/api/products`
- 搜索词会影响结果数和商品列表
- `q + filter + sort` 可以叠加工作
- detail 顶部搜索后会跳回带结果的 storefront
- order 顶部搜索后会跳回带结果的 storefront
- 顶部导航点击后会真实切换筛选结果
- 中英文下头部和搜索都正常
- 旧有购物车、详情、订单、多语言、breadcrumb、source 流程不回退

## 10. 风险与回退策略

主要风险：

- 单文件继续增大，维护成本上升
- 顶部壳层加入后，旧测试定位器可能失效
- 搜索进入 URL 后，现有返回链路需要统一保留 `q`

回退策略：

- 统一通过辅助函数生成 storefront URL 与 detail URL
- 不引入新的路由模式
- 搜索为空时回退到当前无 `q` 的行为
- 顶部导航与工具栏筛选共用状态，避免双份逻辑

## 11. 验收标准

- 三层商城头部在 storefront、detail、order 中统一显示
- 全站页脚在 storefront、detail、order 中统一显示
- storefront 存在真实品类入口区
- 搜索真实作用于当前袜子商品标题、描述和分类
- 搜索与筛选、排序可以叠加工作
- detail / order 顶部搜索能回到结果页
- 多语言与既有购物车、详情、订单流程不回退
- 不新增新的独立 HTML 页面
