# 真实数据看板设计

## 目标

把现有后台首页从基础计数卡片升级为可用于日常经营复盘的数据看板，覆盖净销售额、访问转化率、退款率、SKU 库存预警和热销商品。所有经营指标必须来自真实业务表或受控访问事件，不使用前端固定数字或演示假数据。

## 已确认范围

- 支持近 7 天、30 天和 90 天三个固定时间范围。
- 转化率口径为支付成功订单数除以独立访客数。
- 销售额口径为支付成功金额减去成功退款金额，即净销售额。
- 退款率口径为发生成功退款的独立订单数除以支付成功订单数。
- 热销商品按支付成功商品件数排序，辅助展示商品销售额和退款件数。
- 库存预警展示到 SKU 尺码层级。
- 页面采用已确认的“A：经营总览型”布局。
- 不增加常驻统计进程、外部分析服务或并发后台智能体。

## 总体架构

采用“实时 SQL 聚合 + 轻量访问事件表”。订单、支付、退款、商品和库存继续作为交易事实来源；新增的访问事件只补足独立访客和漏斗阶段数据，不覆盖交易结果。

后台通过统一接口读取看板：

```text
GET /api/admin/analytics?range=7d|30d|90d
```

接口返回稳定的 `summary`、`trend`、`funnel`、`topProducts`、`inventoryAlerts` 和 `period`。将来即使改为每日快照表，前端也不需要改变响应结构。

## 数据模型

新增迁移 `0012_analytics_events` 和表 `analytics_events`：

```text
id              TEXT PRIMARY KEY
event_type      TEXT NOT NULL
visitor_id      TEXT NOT NULL
session_id      TEXT
user_id         TEXT
product_id      TEXT
order_id        TEXT
occurred_at     TEXT NOT NULL
bucket_date     TEXT NOT NULL
dedupe_key      TEXT UNIQUE
metadata        TEXT NOT NULL DEFAULT '{}'
```

索引覆盖：

- `event_type + occurred_at`
- `visitor_id + event_type + occurred_at`
- `product_id + event_type + occurred_at`

`visitor_id` 由服务端根据当前会话生成，同一登录用户在不同设备上按不同访问会话计算，符合“独立访客设备/会话”的常见商城口径。数据库存储 UTC 时间，同时保存按 `Asia/Shanghai` 计算的 `bucket_date`。

允许浏览器上报的事件只有：

- `storefront_visit`：商城列表或详情成功展示。
- `product_view`：商品详情成功展示，并带受验证的商品 ID。
- `cart_add`：加入购物车 API 成功后记录。
- `checkout_start`：非空购物车进入有效结算页。

支付成功由支付业务链路在服务端记录或直接从成功支付事实读取，客户端不能提交 `payment_success`、金额、用户 ID、会话 ID或发生时间。

同一会话的漏斗事件按“事件类型 + 上海日期”去重；商品浏览按“事件类型 + 会话 + 商品 + 上海日期”去重。重复刷新不会抬高独立访客和漏斗人数。

## 指标口径

### 周期

后端根据 `range` 生成 `[start, end)`：

- `7d`：含今天的最近 7 个上海自然日。
- `30d`：含今天的最近 30 个上海自然日。
- `90d`：含今天的最近 90 个上海自然日。

对比周期是紧邻当前周期之前的等长区间。7 天和 30 天趋势按日聚合；90 天按连续 7 日周桶聚合，最后一个桶允许不足 7 天。

### 净销售额

周期内支付成功订单的实收总额，减去周期内状态变为 `succeeded` 的退款金额。部分退款、订单退款和退货退款都计入；失败、处理中和撤销退款不计入。结果允许为负值，不强制归零。

销售额变化使用相对百分比。上期为零时返回 `comparison: null`，前端显示“上期无数据”，不显示无穷大。

### 转化率

```text
支付成功订单数 / storefront_visit 独立 visitor_id 数
```

支付成功订单以周期内首次成功支付时间归属。重复支付回调和重复成功尝试对同一订单只计一次。无访客时转化率返回 `0`。对比变化使用百分点，而不是相对百分比。

### 退款率

```text
周期内发生成功退款的独立订单数 / 周期内支付成功订单数
```

同一订单多次部分退款只计一个退款订单。无支付成功订单时退款率返回 `0`。该比率不截断到 100%，因为当前周期可能处理了更早周期订单的退款；界面始终显示分子和分母避免误读。对比变化使用百分点。

### 转化漏斗

漏斗展示当前周期内各阶段的独立访问会话数：

```text
独立访客 -> 加购会话 -> 发起结算会话 -> 支付成功订单
```

漏斗用于识别流失阶段，不作为订单或收入事实来源。

### 热销商品

只统计周期内支付成功订单行，按商品件数降序，件数相同则按商品销售额降序。返回前 8 项：

- 商品 ID、标题和主图。
- 支付成功件数。
- 商品销售额。
- 成功退款件数。

订单级优惠按订单行商品小计占比分摊，使商品销售额可与订单实收金额对账。退款件数读取成功退款明细；没有退款明细的整单退款按原订单行数量计入。

### SKU 库存预警

读取当前 `product_variants`，不受时间范围影响。严重度固定为：

- `out_of_stock`：不可售或库存小于等于 0。
- `critical`：库存大于 0，且小于等于低库存阈值的一半（向上取整）。
- `low`：库存高于紧急线，但小于等于低库存阈值。

按严重度、剩余库存和商品标题排序，返回商品、SKU、尺码、库存、阈值和严重度。点击行跳转到后台库存页签并通过 SKU 查询参数定位对应记录。

## 接口与安全

新增受限事件写入接口：

```text
POST /api/analytics/events
```

请求只允许 `eventType` 和可选 `productId`。服务端负责身份、时间、日期桶和去重键；未知事件、无效商品和超长请求返回标准错误码。接口按会话限频，重复事件返回成功和 `recorded: false`，避免前端重试制造重复记录。

看板读取接口只允许演示管理员。查询参数只接受固定范围，非法值返回 `400 ANALYTICS_RANGE_INVALID`，不静默扩展任意日期查询。响应不包含访问者、会话、用户或订单的可识别明细。

## 页面设计

后台默认页签升级为经营总览：

1. 顶部标题、数据更新时间和 `7 天 / 30 天 / 90 天` 分段按钮。
2. 第一行五张 KPI 卡：净销售额、转化率、退款率、低库存 SKU、缺货 SKU。
3. 中部左侧为净销售额趋势折线图，右侧为转化漏斗。
4. 底部左侧为热销商品表，右侧为 SKU 库存预警表。
5. 保留现有待处理工作队列和最近订单，但移到上述经营模块之后，避免丢失后台已有操作入口。

视觉延续现有黑、白、灰商城语言，以暖橙色强调销售趋势，以红/琥珀色区分库存严重度。颜色不是唯一状态信号，每个状态同时显示文字标签和数值。

桌面端 KPI 五列，趋势区为二比一双列。中等宽度 KPI 三列并允许换行。小于 640px 时 KPI 两列、图表纵向排列，热销和库存表改为卡片列表，页面不得产生横向滚动。

折线图使用原生 SVG，提供可见坐标标签、键盘可访问的数据点和屏幕阅读器摘要。时间范围使用语义按钮和 `aria-pressed`。所有可点击库存行同时提供明确的“管理库存”链接。

## 页面状态

- 加载：保持页面骨架与时间按钮，指标卡和图表显示稳定尺寸的骨架屏。
- 空数据：显示零值 KPI、空趋势坐标和“当前周期暂无成交/访问”说明，不生成假趋势。
- 部分数据：例如有订单但没有访问事件时，销售正常展示，转化率显示 0 并提示访问采集尚无数据。
- 请求失败：保留当前选择范围，显示错误摘要和“重新加载”按钮。
- 范围切换：禁用当前请求中的时间按钮，旧数据保留并显示局部加载状态，避免页面闪空。
- 响应竞态：只接受最后一次范围请求结果，较慢的旧请求不得覆盖新范围。

## 模块边界

- `lib/database.js`：`0012_analytics_events` 迁移和索引。
- `lib/repositories/analytics-events.js`：事件校验、去重和写入。
- `lib/repositories/admin-analytics.js`：周期计算、经营聚合、排行和库存严重度。
- `lib/routes/analytics-routes.js`：公共受限事件写入。
- `lib/routes/admin-analytics-routes.js`：管理员看板读取。
- `public/js/admin-analytics-dashboard.js`：独立看板模块、请求状态、SVG 图表和响应式渲染。
- `public/js/storefront-app.js`：挂载看板模块并在登录/页签切换时销毁或重载。
- `socks-product-list.html`：看板样式与脚本入口。

现有 `getAdminSummary` 继续提供兼容数据，新的经营看板改用专用分析接口，避免继续扩大通用后台仓储和 `storefront-app.js`。

## 测试策略

### API 与仓储

- 迁移可重复执行且索引存在。
- 浏览器不能伪造用户、会话、时间、订单或金额。
- 访问、商品浏览、加购和结算事件按约定去重。
- 7/30/90 天上海时区边界与前周期对比正确。
- 成功支付只计一次，失败支付和未支付订单排除。
- 净销售额正确处理部分退款、整单退款和重复回调。
- 退款率按独立订单计算且允许超过 100%。
- 热销排行按件数、销售额稳定排序，优惠分摊和退款件数正确。
- SKU 严重度和排序正确。
- 普通用户不能访问管理员分析接口。

### UI

- 默认 30 天，切换 7/90 天会携带正确参数并更新所有模块。
- KPI 显示分子、分母和上期变化；上期为零时不显示无穷大。
- 趋势图和漏斗存在可访问摘要。
- 库存行跳转到正确 SKU。
- 加载、零数据、部分数据和失败重试状态可见。
- 快速切换范围时旧响应不会覆盖新响应。
- 375px 下无横向溢出，键盘可操作时间范围和数据点。

完整 API 与 UI 回归继续固定 `--workers=1`。测试结束后恢复 JSON fixture，并只删除本轮明确生成的上传测试文件。

## 不在本阶段

- 自定义日期范围。
- CSV、图片或报表导出。
- 广告归因、渠道来源和跨设备用户合并。
- 常驻任务、消息队列、第三方分析平台和每日物化快照。
- 实时 WebSocket 推送。
