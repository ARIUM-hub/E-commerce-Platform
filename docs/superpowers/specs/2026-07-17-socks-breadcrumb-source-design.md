# 袜子商城 Breadcrumb 与来源提示设计文档

- 日期：2026-07-17
- 主题：为 `socks-product-list.html` 增加更像真实商城的 breadcrumb 与来源提示文案
- 方向：在不破坏当前黑白灰简约商城风格的前提下，让用户更清楚自己“从哪里来、能回哪里去”

## 1. 目标

在已经完成的列表页、详情页、购物车抽屉、订单页跳转链路基础上，再补一层更真实的电商导航感：

- 详情页顶部能看出当前商品来自哪个结果集
- 用户从购物车回到商品详情时，仍能感知原来的浏览来源
- 订单页 `Continue shopping` 不只是一个按钮，而是带有明确来源说明

这层增强的重点不是新增路由能力，而是补齐“导航语义”和“来源提示文案”。

## 2. 范围

本次设计包含：

- 详情页顶部来源提示区
- 详情页 breadcrumb
- 从购物车进入详情页后的来源提示文案
- 订单页 `Continue shopping` 来源说明

本次设计不包含：

- 新页面
- 多级面包屑体系
- 面包屑点击回退多层逻辑
- 国际化
- 推荐算法或商品数据结构变更

## 3. 设计方向

采用你确认的 `A1` 方向：

- 保留“Back to results”这一层强来源提示
- 同时保留标准 breadcrumb
- 文案风格更接近成熟电商，但视觉仍然保持当前项目的极简黑白灰气质

设计原则：

- 先告诉用户“你从哪里来”
- 再告诉用户“你现在在哪”
- 文案真实，但不喧宾夺主
- 让来源感服务于浏览，而不是把页面做成后台导航

## 4. 页面结构

### 4.1 商品详情页顶部

详情页在现有标题区域上方新增两层信息：

1. 来源提示条
   - 文案样式示例：`Back to results for 运动袜`
   - 辅助信息示例：`当前排序：价格从高到低`
2. Breadcrumb
   - 文案结构示例：`首页 / 袜子专区 / 运动袜 / 轻压运动袜`

展示顺序：

```text
Back to results for ...
当前排序：...
首页 / 袜子专区 / 分类 / 商品名
商品标题 / 价格 / 评分 ...
```

### 4.2 从购物车进入详情页

如果用户是通过购物车抽屉中的 `查看商品` 进入详情页，则详情页顶部仍然使用同一套来源提示结构：

- 如果存在有效来源上下文，则显示结果集来源
- 如果没有来源上下文，则只显示精简 breadcrumb，不显示强来源条

这样能让“从购物车跳详情”这条路径看起来仍像商城浏览的一部分，而不是孤立详情页。

### 4.3 订单页 Continue shopping 区域

订单页中 `Continue shopping` 上方增加来源说明块：

- 主文案示例：`Go back to your last results`
- 次文案示例：`袜子专区 / 运动袜 / 价格从高到低`

按钮仍然是：

- `Continue shopping`

但现在它会配合来源说明一起出现，形成更明确的“返回上一轮浏览结果”语义。

## 5. 文案规则

### 5.1 详情页来源提示

当存在来源分类时：

- 主文案：`Back to results for {分类名}`

当存在来源排序时：

- 辅助文案：`当前排序：{排序名}`

排序文案建议映射：

- `recommended` -> `推荐`
- `price-asc` -> `价格从低到高`
- `price-desc` -> `价格从高到低`
- `newest` -> `最新上架`

### 5.2 Breadcrumb 文案

基础结构：

```text
首页 / 袜子专区 / {分类名可选} / {商品名}
```

规则：

- 如果当前来源分类是 `all`，则省略分类节点
- 最后一项商品名为当前所在页，不作为跳转重点处理

### 5.3 订单页来源说明

当存在来源上下文时：

- 标题：`Go back to your last results`
- 描述：`袜子专区 / {分类名可选} / {排序名可选}`

当没有来源上下文时：

- 标题：`Continue shopping in storefront`
- 描述：`袜子专区 / 全部商品`

## 6. 数据与状态

继续复用现有导航上下文：

- `filter`
- `sort`
- `storefrontHref`

本次不新增后端字段。

前端仅基于已有上下文生成：

- 来源提示主文案
- 排序辅助文案
- breadcrumb 文案
- 订单页来源说明文案

## 7. 交互规则

### 7.1 详情页来源提示条

- 点击主文案区域或返回结果提示，可回到来源列表页
- 如果不存在来源上下文，则不显示可点击的“Back to results”条

### 7.2 Breadcrumb

- 本次以“路径展示”为主，不要求所有节点都可点击
- 至少保证：
  - `首页 / 袜子专区` 可作为低优先级返回入口
  - 当前商品节点为纯文本

### 7.3 订单页 Continue shopping

- 按钮点击后继续沿用已有 `Continue shopping` 跳转逻辑
- 来源说明块本身不需要单独做成复杂交互

## 8. 视觉规则

### 8.1 来源提示条

- 使用浅灰背景和细边框
- 高度低于主卡片，不与商品价格抢层级
- 文案强调“来源”，不是强调“操作危险”

### 8.2 Breadcrumb

- 字号小于商品标题区
- 颜色使用中灰
- 当前商品节点使用更深文字强调当前位置

### 8.3 订单页来源说明

- 作为 `Continue shopping` 上方的信息块出现
- 与按钮形成一组，但视觉层级低于订单确认主信息

整体继续沿用：

- 黑 / 白 / 灰
- 圆角
- 轻边框
- 简洁 hover 状态

## 9. 异常与回退

- 如果没有来源上下文，详情页不显示 `Back to results for ...`，只显示简化 breadcrumb
- 如果分类或排序值异常，回退到默认文案，不显示技术字段原值
- 如果订单页没有来源记录，`Continue shopping` 区域显示默认商城说明

## 10. 测试设计

需要补充：

- 详情页在有来源上下文时显示 `Back to results` 与排序提示
- 详情页在无来源上下文时回退为简化 breadcrumb
- 订单页在有来源上下文时显示来源说明
- 订单页在无来源上下文时显示默认商城说明

同时保持不回退：

- 现有详情页跳转
- 购物车抽屉查看商品跳转
- `Continue shopping` 实际跳转逻辑

## 11. 验收标准

- 详情页顶部出现更像真实商城的来源提示
- 详情页显示 breadcrumb
- 用户从购物车进入详情页时，来源感仍然成立
- 订单页 `Continue shopping` 具备明确来源说明
- 视觉风格与当前页面保持一致
- 不新增后端接口
