# 袜子订单确认页增强设计文档

- 日期：2026-07-17
- 主题：为 `socks-order-confirmation.html` 增加订单价格摘要与推荐返购商品
- 方向：让订单确认页更像真实商城的下单结果页，而不是只有基础确认信息

## 1. 目标

在 2026 年 7 月 17 日已经可用的订单确认页基础上，继续补两类高价值信息：

- 订单价格摘要
- 推荐返购商品

这样用户在查看结果页时，不只知道订单已完成，还能继续理解本次订单金额结构，并看到后续可继续购买的商品。

## 2. 范围

本次设计包含：

- 订单确认页价格摘要区
- 推荐返购商品区
- 前端订单快照字段扩展
- 订单页商品推荐渲染

本次设计不包含：

- 实时推荐算法
- 后端订单查询接口
- 用户专属推荐
- 多页订单中心

## 3. 设计方向

采用“轻商城结果页”方案：

- 保持黑白灰简约风格
- 保持页面结构克制
- 增加真实商城常见的下单后延伸模块

## 4. 页面结构

订单确认页调整为三层：

1. 状态区
   - `Order confirmed`
2. 订单摘要区
   - Order number
   - Items
   - Estimated delivery
   - Subtotal
   - Savings
   - Estimated total
3. 推荐返购商品区
   - `You may also like`
   - 2 到 3 张轻量商品卡

## 5. 数据设计

订单快照新增以下字段：

- `subtotal`
- `savings`
- `total`
- `purchasedProductIds`

示例：

```json
{
  "orderNumber": "SOCK-20260717-001",
  "itemCount": 3,
  "estimatedDelivery": "Saturday, July 18, 2026",
  "subtotal": 187,
  "savings": 54,
  "total": 133,
  "purchasedProductIds": ["sock-02", "sock-05"]
}
```

## 6. 推荐逻辑

推荐返购商品使用当前已有商品接口数据，在前端按以下规则筛选：

1. 请求 `GET /api/products?filter=all&sort=recommended`
2. 排除当前订单中已购买的商品
3. 取前 3 个结果

这样可以保证：

- 不推荐本次已买商品
- 保持与商城列表默认推荐顺序一致

## 7. 视觉规则

- 价格摘要区继续使用浅灰面板样式
- 推荐商品区使用更轻的卡片密度
- 推荐卡片只保留必要信息：
  - 系列名
  - 标题
  - 现价
  - 配送文案

## 8. 响应式要求

- 推荐商品区在窄屏下改为单列
- 价格摘要各行保持两端对齐
- 不允许推荐区撑破页面宽度

## 9. 测试设计

需要补充：

- 订单页能显示价格摘要字段
- 订单页能显示推荐返购商品
- 推荐商品不包含当前订单已购商品

## 10. 验收标准

- 订单页展示 `Subtotal`、`Savings`、`Estimated total`
- 订单页展示推荐返购商品
- 推荐商品不包含当前订单里的商品
- 空状态页仍然正常显示
