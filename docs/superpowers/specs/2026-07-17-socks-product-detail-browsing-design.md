# 袜子商品详情浏览增强设计文档

- 日期：2026-07-17
- 主题：为 `socks-product-list.html` 的商品详情视图增加相关推荐与上一件/下一件切换
- 方向：让商品详情页从“单页查看”升级为“可连续浏览”的轻商城详情体验

## 1. 目标

在已经支持统一入口详情页的基础上，继续补齐两段高频浏览行为：

- 相关推荐
- 上一件 / 下一件切换

这样用户在进入单品详情后，不需要总是返回列表页，也能持续浏览商品。

## 2. 范围

本次设计包含：

- 详情页顶部或主体内的上一件 / 下一件导航
- 详情页相关推荐模块
- 详情页在带有 `filter` / `sort` 上下文时的连续浏览逻辑

本次设计不包含：

- 多图轮播
- 详情页评价列表
- 相关推荐加购快捷操作
- 真正个性化推荐算法

## 3. 设计方向

继续保持统一入口方案：

- 商品详情页仍使用 `socks-product-list.html?view=detail&id=...`
- 如果 URL 中带有来源 `filter` 与 `sort`，上一件 / 下一件就在这个来源结果集内切换
- 如果没有来源上下文，则在默认商品结果集内切换

相关推荐则保持轻量：

- 使用已有商品数据
- 排除当前商品
- 展示 3 个卡片

## 4. 页面结构

详情页增加两块：

1. 连续浏览导航
   - `Previous`
   - `Next`
2. 相关推荐
   - `You may also like`
   - 3 张轻量商品卡

## 5. 连续浏览规则

详情页读取当前 URL 参数：

- `id`
- `filter`
- `sort`

然后用同一组条件获取当前上下文商品列表：

```text
GET /api/products?filter=<filter>&sort=<sort>
```

规则：

- 找到当前商品在结果集中的位置
- 前一个商品作为 `Previous`
- 后一个商品作为 `Next`
- 链接继续保留原来的 `filter` 和 `sort`

如果当前商品是该结果集的第一个或最后一个：

- 对应方向按钮显示为禁用态

## 6. 推荐规则

相关推荐使用当前已有商品接口数据：

1. 请求 `GET /api/products?filter=all&sort=recommended`
2. 排除当前详情商品
3. 取前 3 个

这样可以保证：

- 相关推荐不重复当前商品
- 与商城默认推荐顺序一致

## 7. 空与异常处理

- 如果详情商品不存在，仍保持现有 `Product not found`
- 如果相关推荐加载失败，不阻塞主体详情展示
- 如果连续浏览上下文加载失败，则上一件 / 下一件显示禁用态

## 8. 视觉规则

- 上一件 / 下一件使用轻按钮样式，层级低于主加购按钮
- 相关推荐卡片沿用当前黑白灰商城语言
- 不做复杂 hover 体系扩展，只保持现有按钮和卡片运动语言

## 9. 测试设计

需要补充：

- 详情页显示相关推荐且不包含当前商品
- 详情页在带来源上下文时显示正确的上一件 / 下一件链接
- 点击 `Next` 后能进入下一件详情并保留上下文参数

## 10. 验收标准

- 详情页显示 `You may also like`
- 相关推荐不包含当前商品
- 详情页支持上一件 / 下一件连续浏览
- 切换时保留原有 `filter` 和 `sort`
- 不新增新的后端接口
