# 袜子商品卡评分增强设计文档

- 日期：2026-07-17
- 主题：为 `socks-product-list.html` 的商品卡增加评分与评论数信息
- 方向：保留黑白灰简约基底，补充真实商城式口碑信息

## 1. 目标

在不破坏当前页面简约视觉风格的前提下，为袜子商品列表卡片补充更像真实电商商品卡的评分信息，让用户在浏览商品时除了看到标题、价格、折扣外，还能快速感知商品口碑。

本次增强聚焦于：

- 增加星级视觉、评分值、评论数
- 为部分商品增加 `Top rated` 口碑标签
- 保持页面整体黑、白、灰风格不变
- 保持当前后端和购物车交互逻辑不被干扰

## 2. 范围

本次设计包含：

- 商品数据字段扩展
- 商品卡评分区布局设计
- 商品卡评分区视觉规则
- 列表页渲染逻辑调整
- 接口数据与前端渲染测试补充

本次设计不包含：

- 配送时效
- Prime / 免邮类提示
- 库存紧张、热卖、近期购买人数
- 购物车协议改动
- 结算流程改动

## 3. 设计方向

### 3.1 整体风格

采用“折中方案”：

- 保留当前页面的简约精品电商基底
- 引入真实商城常见的星级和评论数信息
- 避免直接复制高密度平台电商视觉

结果应当体现为：

- 信息更真实
- 决策信号更强
- 版面仍然克制，不显拥挤

### 3.2 评分区风格

评分区采用“星级视觉版”：

- 使用视觉星级符号
- 显示明确评分值，例如 `4.7`
- 显示评论数，例如 `1,284 reviews`
- 推荐商品可显示 `Top rated`

不采用纯文本评分，也不采用高饱和平台化评分样式。

## 4. 信息层级设计

商品卡信息层级调整为：

1. 系列名、商品标题、品类
2. 价格、原价划线、折扣
3. 评分区
4. 描述文案
5. 尺码选择与加入购物车

这样安排的原因：

- 用户先确认商品是什么、多少钱
- 然后快速判断口碑如何
- 最后再看详细描述并执行购买动作

评分区不放在标题同行，也不压在描述段落里，避免卡片主信息显得零碎。

## 5. 评分区布局设计

### 5.1 放置位置

评分区放在价格区下方、描述文案上方，作为一个独立的信息层。

### 5.2 组成内容

评分区由以下内容组成：

- 星级图形
- 评分值
- 评论数
- `Top rated` 标签，仅部分商品展示

推荐结构：

```text
★★★★★ 4.7  1,284 reviews  Top rated
```

实际样式上不要求所有元素等权重显示，视觉重点应为：

- 第一优先：评分值
- 第二优先：星级
- 第三优先：评论数
- 第四优先：`Top rated`

### 5.3 密度控制规则

为避免卡片变得过满，需要遵守这些规则：

- 评分区只占一行
- 评论数统一使用英文商城表达，例如 `1,284 reviews`
- `Top rated` 仅在部分商品上出现，不全量铺开
- 不再额外增加“评分说明文案”或二级口碑文案

## 6. 视觉规则

### 6.1 颜色

保持黑白灰体系：

- 星级：深灰，不使用高饱和金色
- 评分值：接近主标题的深色
- 评论数：中灰
- `Top rated` 标签：浅灰底、深灰字

### 6.2 字重与对比

- 评分值比评论数更强调
- 评论数保留较弱对比，避免抢价格信息
- `Top rated` 只作为轻标签存在，不成为主视觉

### 6.3 间距

- 价格区与评分区之间：`8px - 10px`
- 评分区与描述区之间：`8px - 10px`
- 评分区内部元素保持紧凑但不粘连

### 6.4 风格边界

不采用以下视觉方式：

- 金色星星
- 蓝色链接式评论数
- 大面积标签背景
- 两行口碑信息堆叠

这些做法会让页面偏向平台电商，而不是当前项目的简约商城方向。

## 7. 数据设计

### 7.1 新增字段

在商品数据中新增以下字段：

- `ratingValue`
  示例：`4.7`
- `reviewCount`
  示例：`1284`
- `isTopRated`
  示例：`true`

示例结构：

```json
{
  "id": "sock-01",
  "title": "极简中筒袜",
  "price": 39,
  "ratingValue": 4.7,
  "reviewCount": 1284,
  "isTopRated": true
}
```

### 7.2 字段规则

- `ratingValue` 使用数值类型，前端按一位小数展示
- `reviewCount` 使用整数类型，前端负责格式化为带千分位的文本
- `isTopRated` 为布尔值，决定是否显示标签

### 7.3 接口影响

不新增接口，不改接口路径，不改筛选排序协议。

仅扩展 `GET /api/products` 返回的商品字段。

## 8. 前端渲染设计

### 8.1 渲染职责

前端商品卡新增评分区渲染逻辑，负责：

- 将 `ratingValue` 渲染为评分值文本
- 将 `reviewCount` 格式化为评论数字符串
- 渲染星级视觉元素
- 根据 `isTopRated` 条件显示标签

### 8.2 星级呈现方式

建议使用轻量文本或内联图形方式渲染星级，而不是引入额外图片资源。

原因：

- 适合当前纯 HTML / CSS / 原生 JS 技术栈
- 更便于保持黑白灰风格一致
- 更便于测试和响应式控制

### 8.3 空缺处理

本次数据源中所有商品都应补齐评分字段，不引入“无评分商品”的特殊状态。

这样可以保持列表页视觉统一，并减少额外分支逻辑。

## 9. 响应式设计

移动端需要继续保持卡片可读性，要求：

- 评分区优先保持单行
- 若空间紧张，优先缩小评论数字号和标签内边距
- 不允许出现星级、评论数、标签明显重叠或换行错位

评分区在窄屏下的优先级顺序为：

1. 保留评分值
2. 保留星级
3. 保留评论数
4. 最后才压缩 `Top rated` 标签尺寸

不建议在移动端隐藏评分区任意核心信息。

## 10. 测试设计

### 10.1 数据层测试

验证 `GET /api/products` 返回结果中包含：

- `ratingValue`
- `reviewCount`
- `isTopRated`

并且字段值类型符合预期。

### 10.2 页面渲染测试

验证商品卡可见：

- 星级视觉元素
- 评分值文本
- 评论数文本
- 部分商品的 `Top rated` 标签

### 10.3 响应式测试

验证在较窄视口下：

- 评分区仍存在
- 评分区布局未重叠
- 商品卡整体未出现明显破版

## 11. 验收标准

### 11.1 功能验收

- 商品接口返回新增评分字段
- 列表页商品卡展示评分、评论数
- 指定商品显示 `Top rated`

### 11.2 视觉验收

- 页面仍保持黑白灰简约风格
- 评分区不抢价格和标题的主层级
- 卡片信息更真实，但不显拥挤

### 11.3 稳定性验收

- 不影响现有筛选排序
- 不影响当前购物车交互
- 现有测试和新增测试都通过

## 12. 实现备注

- 这是对“商品卡信息可信度”的一次增强，不是整页改版
- 本轮优先补口碑信息，不扩展配送、库存、促销等其他电商模块
- 如果后续继续增强真实商城感，可以在下一轮继续加入配送与库存信号
